# macOS external-update recovery

Use this reference only after the normal OpenAI installation flow fails specifically at the Chrome Web Store distribution step.

## Known values

- Official OpenAI setup documentation: `https://developers.openai.com/codex/chrome-extension`
- Expected Chrome extension ID at publication: `hehggadaopoacecdllhhajmbjkdcmajg`
- Chrome Web Store page: `https://chromewebstore.google.com/detail/chatgpt/hehggadaopoacecdllhhajmbjkdcmajg`
- Google update service: `https://clients2.google.com/service/update2/crx`
- Chrome user-data root on macOS: `~/Library/Application Support/Google/Chrome`
- Recovery configuration:
  `~/Library/Application Support/Google/Chrome/External Extensions/hehggadaopoacecdllhhajmbjkdcmajg.json`

Expected JSON:

```json
{
  "external_update_url": "https://clients2.google.com/service/update2/crx"
}
```

Chrome interprets this as an external preference download: Chrome contacts the declared update URL, downloads the signed package, and maintains normal update behavior. The JSON file is not the extension package.

## Decision sequence

1. Verify the official extension ID from current OpenAI material.
2. Confirm Chrome is not organization-managed and no policy blocks the extension.
3. Check whether the configuration already exists. Never overwrite unknown content.
4. Explain that Chrome will be closed/restarted and that the file directs Chrome to Google’s service.
5. Obtain confirmation, then create the file.
6. Restart Chrome and allow time for the update check.
7. If the extension does not appear, test reachability of the Google update endpoint without downloading or executing arbitrary files.
8. If the endpoint is unavailable, stop and report the network dependency.
9. After installation, restart ChatGPT and check **Settings → Computer Use**.

## Verification signals

Strong signals include:

- An extension directory at `PROFILE/Extensions/hehggadaopoacecdllhhajmbjkdcmajg/VERSION/`.
- `manifest.json` names ChatGPT and uses Google’s update URL.
- Chrome Secure Preferences records `from_webstore: true`.
- Chromium manifest location `6`, when present, means `kExternalPrefDownload`: an external preference installed from an update URL. It does not mean an unpacked developer extension.
- A later visit to `https://chatgpt.com/work/extension/installed` supports completion but is not sufficient by itself.

Do not publish profile names, email addresses, absolute home paths, browsing history, Chrome preference files, native-host logs, or tokens when documenting a recovery.

## Connection is a separate layer

The extension may be installed while ChatGPT still shows disconnected. Check these separately:

- ChatGPT desktop is signed in and current.
- The Chrome plugin is installed in ChatGPT/Codex.
- macOS allows ChatGPT access to Chrome files when prompted.
- Chrome’s native messaging manifest exists under `NativeMessagingHosts` and was generated by the OpenAI application.

Do not hand-write the native messaging manifest. Its executable path and plugin version are application-managed.

## Rollback

Remove only the recovery JSON after confirmation. This prevents future external-preference discovery but does not uninstall the extension already registered in Chrome. Uninstall from `chrome://extensions` if requested.
